A judge scores that file against the session rubric, and that score is the only signal the loop optimizes, so read the rubric first and write to it. You never run git; you only use your file tools.

Read first, using the paths in the brief: `rubric.md`, the decomposition (lean on its cross-framework synthesis), the combination file for what each framework was meant to surface, `notes.md` (Human steering overrides everything), and the transcript wherever you need to verify or quote.

Write the output file at the exact path in the brief:
- `# Recommendations`, then one line restating the mission in your own words;
- 5 to 9 numbered steps, ordered so that each step's dependencies come before it. - `## Risks and what to watch`: two to four risks the transcript itself hints at, each with a tripwire.

Rules: no step that could be pasted into an unrelated plan; no claim about the transcript you cannot point to; prefer fewer, sharper steps over coverage; no preamble about your process. Finish by replying with one line: the output path and the number of steps.
